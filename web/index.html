Technical Interview Cheatsheet & Architecture Matrix

Gunakan panduan ini saat sesi screen-sharing wawancara teknis backend fintech

1. Double-Entry Bookkeeping

Uang tidak pernah di-update sembarangan (UPDATE balance = balance - X). Setiap perpindahan wajib memiliki pasangan DEBIT dan CREDIT yang mutlak seimbang (ΣDebit = ΣCredit). Ini menjamin keterlacakan audit (*auditability*) dan invariant saldo non-negatif.

2. Deterministic Lock Ordering (Anti-Deadlock)

Jika Transaksi 1 lock Akun A → B, sementara Transaksi 2 lock Akun B → A, database akan mengalami deadlock. Dengan membandingkan UUID kedua akun secara leksikografis (selalu lock ID lebih kecil dulu), circular wait deadlock dieliminasi secara matematis.

3. Distributed Idempotency State Machine

Menggunakan Redis atomic SETNX dengan 3 status: ACQUIRED, IN_PROGRESS (menolak duplikasi konkuren via 409 Conflict), dan COMPLETED (mengembalikan respons ter-cache seketika tanpa mutasi saldo berulang jika network retry).

4. Zero-Trust Security (AES-256-GCM & HMAC)

Data identitas dienkripsi di level aplikasi menggunakan AES-256-GCM (Authenticated Encryption). Verifikasi tanda tangan API menggunakan hmac.Equal konstan-waktu untuk menangkal timing attacks, plus toleransi timestamp ±5 menit untuk mitigasi Replay Attack.

5. Automated 3-Way Reconciliation

Menjawab pertanyaan krusial bank integration: *"Bagaimana jika bank mencatat transaksi berhasil tapi gateway timeout?"* Engine rekonsiliasi membandingkan laporan bank eksternal terhadap mutasi ledger internal untuk mendeteksi MATCHED (100% cocok), DISCREPANCY_AMOUNT (selisih nominal), atau MISSING_IN_GATEWAY.
